# sauna-map 規約（状態管理・コンポーネント・パフォーマンス）

このファイルは `frontend/src/components/sauna-map/` 配下を編集するときに読み込まれます。CSS・アクセシビリティの規約は `frontend/src/AGENTS.md`、全体方針はリポジトリルートの `AGENTS.md` を参照してください。

## 1. 状態管理構造 (`SaunaMapContext`)
状態管理は巨大な単一ステートを避け、責務ごとの専門 Provider にモジュール分割されています（`src/components/sauna-map/context/` 参照）。コンポーネントやロジックを追加する際は適切な Context / Hook を利用・拡充してください。

- **専用フックを直接使うこと**: 消費側は `useSaunaUI` / `useVisitsData` / `useVisitsStatus` / `useVisitsActions` / `useVisitFiltersContext` / `useSaunaEditorState` / `useSaunaEditorActions` / `useSaunaMapState` のうち、実際に必要なものだけを個別に呼びます。さらに操作関数だけなら `useSaunaUIActions` / `useVisitFilterActions` / `useSaunaMapActions`、状態のみなら `useSaunaMapStateValue`、画面幅判定だけなら `useSaunaViewport` を使ってください。複数の Context を 1 オブジェクトに束ねるフック（旧 `useSaunaMap` / 旧 `useSaunaVisitsData` / 旧 `useVisitsCRUD` / 旧 `useSaunaEditor`）は、どれか 1 つの状態変化で全消費側が再レンダリングされるため復活させないでください。
- **Provider 間は最小の Context だけを購読すること**: `VisitsCRUDProvider` は `useSaunaUIActions()`、`EditorProvider` は `useSaunaViewport()` + `useSaunaUIActions()` + `useVisitFilterActions()`、`MapStateProvider` は `useSaunaViewport()` を使います。ここで統合フックへ戻すと、モーダル開閉・検索入力・テーマ変更が無関係な Provider まで連鎖的に再レンダリングさせます。
- **操作関数しか要らない消費側は `useSaunaEditorActions` / `useSaunaMapActions` を使うこと**: `useSaunaMapState()` は state と actions を束ねるため、これを購読すると無関係な状態変更でも再レンダリング対象になります。`MapStateProvider`（`startEditing` / `cancelEditing` / `startCreate` のみ）と `VisitList` / `DesktopSidebar` は `useSaunaEditorActions()`、`VisitForm` は `useSaunaMapActions()` を使うこと。
- **地図（`SaunaMapLayer`）は `useSaunaUI()` を購読しないこと**: UI 状態にはトースト・モーダル・メニューの開閉が含まれるため、購読すると通知 1 件で地図とマーカー全体が再描画されます。画面幅は `useSaunaViewport()`、通知は `useSaunaUIActions()` から取得してください（`SaunaMapLayer.test.tsx` の「does not re-render the map when a toast is shown」が検査しています）。
- **Provider は `SaunaMapContext.tsx` に一本化**: `SaunaMapProvider` が `UIProvider` → `VisitsCRUDProvider` → `VisitFiltersProvider` → `EditorProvider` → `MapStateProvider` を直接入れ子にします。複数 Provider をまとめるだけの中間ファイルは作らないでください（旧 `VisitsDataContext.tsx` は削除済み）。
- **訪問データは変化の頻度で 3 つに分けること**: `VisitsCRUDProvider` は記録本体（`useVisitsData`）・読み込み／保存中／認証などの状態（`useVisitsStatus`）・操作関数（`useVisitsActions`）を別々の Context で配ります。操作関数は `visits` に依存させないでください。更新・履歴削除は ID ではなく対象の記録（`SaunaVisit`）を受け取り、インポートの重複判定とエクスポートは `useSaunaVisits` の `getVisits()`（エフェクトで同期した ref）から読みます。`visits` から引く形に戻すと、記録が 1 件変わるたびに `useVisitsActions` の参照が変わり、`DesktopSidebar` などの操作関数しか使わない消費側まで再レンダリングされます（`SaunaMapContext.test.tsx` の「記録が変わっても VisitsStatus / VisitsActions の参照が変わらないこと」が検査しています）。画面全体の親である `SaunaMapContent` は `useVisitsData` を購読しないこと。`useSaunaVisits` は `{ visits, status, actions }` に分けて返し、`status`／`actions` の組み立てと参照の安定化（`useMemo`）も受け持ちます。Provider はそれを各 Context へ渡すだけにし、平らなオブジェクトを Provider 側で分割代入して詰め直す形へ戻さないでください（操作を足すたびに 3 か所を書き写すことになり、漏れが出ます）。
- **訪問データとフィルターの分離**: 訪問データ本体は `useVisitsData`、インポート/エクスポートは `useVisitsActions`、絞り込み結果・フィルター状態・統計は `useVisitFiltersContext` から取得します。CRUD しか使わない画面（`DesktopSidebar` など）がフィルターを購読すると、検索欄の 1 文字入力ごとに再レンダリングされます。
- **入力中のフォーム値は `useSaunaEditorForm` から**: 編集フォームの `form` / `setForm` / `imageUploading` は専用の `EditorFormContext` に分離しています（`useSaunaEditorState` には含まれません）。これを EditorState 側へ戻すと、1 文字入力するたびに `SaunaMapContent` / `DesktopSidebar` / `VisitList` まで再レンダリング対象になります。同じ理由で、`useVisitForm` の `handleSubmit` は依存配列に `form` を入れず `formRef` から最新値を読み、`useEditorState` が返す操作関数は必ず `useCallback` で参照を安定させること（`SaunaMapContext.test.tsx` の「フォーム入力で EditorState / EditorActions の参照が変わらないこと」が検査しています）。
- **タグ絞り込みの初期値は URL から**: 統計ページのタグクラウドは `/?tag=...` で地図へ遷移し、`useVisitFilters` の `getInitialFilters()` がこれを `selectedTag` の初期値として読みます。地図は `ssr: false` で描画されるため初期値算出で `window` を参照して構いません。
- **地図のディープリンク選択は `queueMicrotask` 経由で行うこと**: 統計ページ等から `/?id=xxx` で遷移した際の初期自動選択（`useMapViewState`）は、カスケードレンダリング防止ルール (`eslint react-hooks/set-state-in-effect`) を満たすため `queueMicrotask` 内で `setSelectedId` / `setMapTargetOverride` を呼び出し、モバイル時はシートを最小化 (`"min"`) します。
- **モバイルのシート位置制御は Context 側に集約**: 編集の開始／終了に伴う `snapPosition` の切り替えは `MapStateContext` の `handleEditVisit` / `handleCancelEditing` / `handleEditingFinished` が担います。画面コンポーネント側で `startEditing` + `setSnapPosition` を組み合わせて再実装しないでください。
- **編集の終了は必ず `MapStateContext` 経由にすること**: `VisitForm` のキャンセルは `EditorContext` の `cancelEditing` ではなく `handleCancelEditing()` を呼びます。保存の完了は `handleSubmit(e, handleEditingFinished)` のように完了コールバックを渡して伝えること（`EditorProvider` は `MapStateProvider` の親でシート位置を直接触れないため、`useVisitForm` の `handleSubmit` は保存成功時だけ `onCompleted` を呼ぶ設計にしてあります）。ここを `editor.cancelEditing()` の直接呼び出しに戻すと、モバイルで保存・キャンセルしてもシートが `full` のまま地図が隠れます。
- **セッション確認と初回の一覧読み込みは `useVisitSession` に集約**: 地図（`useSaunaVisits`）と統計ページ（`useStatsData`）は、どちらも `hooks/useVisitSession.ts` で `getSession` → `list` を行います。画面ごとに同じ手順を書き直さないこと（エラー文言や、一覧だけ失敗したときの扱いが画面間でずれます）。localStorage から同期的に先読みするか（`useInitialVisits(seedFromStorage)`）は `useSaunaVisits` が使う Repository の `dataSource` から決めます。`DATA_SOURCE` を別に参照すると、Repository と初期値の出所が食い違ったときに気付けません。
- **保存中の状態は件数で持つこと**: `useSaunaVisits` の `saving` は実行中の更新系操作の数（`pendingMutations > 0`）から求めます。真偽値 1 つに戻すと、並行した操作の片方が終わった時点で、もう片方の実行中に `saving` が `false` へ戻ります。
- **保存失敗のトーストを二重に出さないこと**: CRUD の失敗通知は `useSaunaVisits` の `runMutation` がRepository のエラー文言（409 競合・通信障害・localStorage の容量超過）で出す唯一の担当です。`useVisitCrud` 側で `if (!success) showToast(...)` を足すと、`useToast` は単一 state のため後勝ちで上書きされ、競合や通信障害まで別の原因にすり替わって表示されます（`useVisitCrud.test.ts` の「トーストを重ねないこと」が検査しています）。成功時の通知だけ呼び出し側で行うこと。
- **フォームは開くたびに先頭から表示すること**: 一覧とフォームは同じスクロール領域を共有するため、`VisitFormView` はマウント時と `editingId` の変化時に親要素（スクロール領域）の `scrollTop` を 0 に戻します。新規登録では見出し直下の `.location-status` が場所の選択状態を示し、デスクトップでは場所を選ぶまで地図側にも `MobilePinHint`（`variant="desktop"`、キャンセルボタンなし）を出します。
- **訪問履歴の削除は確認後だけ実行すること**: `VisitHistorySection` は削除候補の index をローカル state に保持し、`ConfirmModal` で対象日を確認してから `onDeleteEntry` を呼びます。削除ボタンから `removeHistoryEntry()` を直接呼ぶ実装へ戻すと、スクロール中の誤タップで履歴が即時消去されます。

## 2. ディレクトリ ＆ コンポーネント構造
- **コンテナは props の上書き機構を持たないこと**: `VisitList` / `VisitForm` / `DesktopSidebar` / `ShareModal` は Context から値を集めて `*View` へ渡すだけのコンテナです。`Partial<...ViewProps>` を受け取って `props.x ?? ctx.x` と書く方式は復活させないでください（誰も props を渡しておらず、型エラーも握り潰します）。テストは props を直接渡せる `VisitListView` などの `*View` を描画すること。
- **レスポンシブ設計**: PC表示 (`DesktopSidebar.tsx`) と モバイル表示 (`BottomSheet.tsx`, `MobileNavBar.tsx`) の責務を明確に分けること。`MOBILE_BREAKPOINT = 768` は「768px 未満がモバイル」を意味するため、CSS はモバイル側を `@media (max-width: 767px)`、デスクトップ側を `@media (min-width: 768px)` にします（768px の両方へモバイルCSSを当てないこと）。ボトムシートの 1 段移動（タップ・↑↓キー・フリックの 3 経路）は `SNAP_ORDER` / `stepSnap()` に集約しており、端では `onSnapChange` を呼びません（`min` / `full` の分岐を各ハンドラへ書き戻さないこと）。また、選択中のサウナがある場合はモバイルボトムシート上部のバッジからワンタップでシートを最小化し地図を確認できます。
- **クイックフィルターチップの可視化**: 検索欄・ステータス絞り込み・カスタムフィルター（都道府県・評価など）のアクティブな条件は `QuickFilterChips` にまとめられ、リスト上部で個別に解除（×ボタン）できるようにしています。
- **共通コンポーネントは 1 ファイル 1 コンポーネント**: `components/common/` は `RatingStars` / `WishlistChip` / `VisitTagList` / `VisitComment` / `VisitImagePreview` / `VisitMetaInfo` / `RouteLink` をそれぞれ同名のファイルに置き、利用側は個別ファイルから import します（`common/index.ts` は `markerIcon` など地図専用のモジュールも再エクスポートするため、一覧やフォームから経由させないこと）。旧 `common.tsx` のような寄せ集めのファイルは作らないでください。
- **ユーティリティ**: 純粋関数ロジックは `src/components/sauna-map/utils/` に抽出し、単体テストを記述すること。記録の履歴操作は `visitHistory.ts`、localモードの保存済み記録の復元は `savedVisits.ts`、統計・集計は `visitStats.ts` に分けています。
- **タグ文字列の分解**: フォームのカンマ区切りのタグ文字列は `utils/form.ts` の `toNormalizedTags()` で配列にすること（Repository やコンポーネントで `split(",")` を書き直さないこと）。区切りは `TAG_SEPARATOR_PATTERN`（半角カンマ・全角カンマ「，」・読点「、」）で、重複したタグは最初の 1 つだけ残します。
- **バウンディングボックス判定**: 緯度経度のバウンディングボックス判定には `utils/geo.ts` の `isInBounds()` を使うこと。
- **検索キーワードマッチング**: 検索文字列からの安全な正規表現生成および横断検索の判定には `utils/search.ts` の `createSearchRegex()` / `matchesSearchKeyword()` を使うこと。
- **保存ボタンの非活性判定**: バリデーションやアップロード状態に伴う保存ボタンブロック理由の取得には `utils/form.ts` の `getSubmitBlockedReason()` を使うこと。
- **記録のステータス判定**: `visit.status ?? "visited"` を直書きせず、`utils/visitStatus.ts` の `getVisitStatus()` / `isVisited()` / `isWishlist()` を使うこと（旧形式データの既定値の解釈が地図・一覧・統計でずれるのを防ぎます）。
- **同梱JSONは初期データとしてだけ使うこと**: `utils/savedVisits.ts` の `loadSavedVisits()` は保存があれば保存側だけを返します。同梱JSON（`src/data/sauna-visits.json`）を毎回連結する実装へ戻すと、保存側の同一IDが捨てられ、デモ記録の編集・削除が再読み込みで元へ戻ります（`utils/savedVisits.test.ts` が検査しています）。同梱JSONの zod 検証は保存が無い／読めないときだけ行います（約1,600行あるため、通常の起動で毎回検証しないこと）。
- **読めなかった保存済み記録を捨てて保存しないこと**: `loadSavedVisits()` は検証に通らなかった要素を `unreadable` として生の値のまま返し、`LocalVisitRepository.persist()` は毎回それを末尾へ書き戻します。画面には出さず、`useSaunaVisits` が件数をトーストで伝えます。検証に通った分だけで保存し直す実装へ戻すと、1件でも壊れた記録があった場合、次の保存でその記録が localStorage から完全に消えます。保存値全体が JSON として壊れている・配列でない場合も、表示は同梱JSONへ切り替えつつ生の保存値（パースできなければ文字列のまま）を `unreadable` の 1 要素として返します。ここで空の `unreadable` を返すと、次の保存で壊れた保存値が同梱JSONで上書きされます。
- **`LocalVisitRepository` は保存値をキャッシュしないこと**: 更新系は毎回 `load()` で localStorage の最新値を読んでから変更を当てます。読み込み結果をキャッシュして保存の土台にすると、別タブがその後に保存した記録を古い配列で上書きして消します。画面側は `useSaunaVisits` が localモードだけ `storage` イベントを購読して `reload()` し、別タブの追加・削除を表示へ反映します。
- **`localStorage` は必ず `utils/storage.ts` 経由**: 読み書きは `readStorage()` / `writeStorage()` を使うこと。Safari のプライベートモードや容量超過では例外が飛ぶため、直接触ると 1 箇所の try/catch 漏れで画面が落ちます。`writeStorage()` の戻り値は「保存できたか」で、容量超過の通知（`useSaunaVisits`）に使っています。読めなかったときだけ既定値へ倒したい場合は `readStorage(key, onErrorValue)` の第 2 引数を使うこと（テーマ判定がこれに依存しています）。
- **今日の日付**: `new Date().toISOString().split("T")[0]` を書かず `utils/date.ts` の `getTodayDate()` を使うこと。UTC ではなく利用者のローカル日付を返すため、日本時間の深夜帯に前日になることを防ぎます（`form.ts` は `visitHistory.ts` に依存しているため、両方から使うこの関数だけ別モジュールに置いています）。「昨日」のような相対日付も `getDateDaysAgo(daysAgo)` を使い（`getTodayDate()` はその薄いラッパー）、コンポーネント側で `new Date()` から年月日を組み立て直さないこと。なお、これらの関数のテストは実行環境のタイムゾーンに依存する（ローカルの JST では通り、CI の UTC では落ちる）ため、`vitest.config.ts` で `TZ=Asia/Tokyo` を固定しています。この設定を外さないこと。
- **日付の表示は `formatDisplayDate()` / `formatShortDate()` を通すこと**: 保存値の `YYYY-MM-DD` を画面へそのまま出さず、カード・ポップアップ・削除確認は `utils/date.ts` の `formatDisplayDate()`（2026年10月4日（日））、コンパクト行・履歴一覧・シェア画面のように幅の限られた場所は `formatShortDate()`（2026/10/4）を使います。どちらも実在しない日付や形式の違う値は元の文字列のまま返します。表示は `<time dateTime={保存値}>` で包んで機械可読な値を残してください。
- **行きたい記録に日付を出さないこと**: 行きたい記録にはフォームに「行った日」の入力欄が無く、保存値の `date` は登録時の既定値に過ぎません。`VisitMetaInfo` には `isWishlist` を渡し（一覧カード・コンパクト行の展開部・地図ポップアップ）、シェア画面も同じ扱いにします。コンパクト行の 2 行目だけ日付を隠し、他の表示で「日付:」を出す状態へ戻さないでください。
- **行きたい記録に評価を出さないこと**: 一覧・カード・地図ポップアップ・ピンの評価バッジ・シェア画面へ渡す評価は `utils/visitStatus.ts` の `getDisplayRating()` を通します（行きたい記録は 0）。フォームは行きたいのとき評価欄を隠しますが、行った→行きたいへ切り替えた記録やインポートした記録は評価を持ったままのため、`visit.rating` をそのまま渡すと「まだ行っていないのに ★5」と表示されます。保存値は変えません（行ったへ戻すと評価も戻る）。
- **未評価は行った記録だけで示すこと**: `RatingStars` は評価 0 で何も描画しませんが、行った記録では `showUnrated` を付けて「未評価」を出します（カード・ポップアップ）。付け忘れと意図的に付けていないことの区別が付かなくなるため外さないこと。行きたい記録に付けると全件に「未評価」が並ぶため付けません。コンパクト行は行が騒がしくなるため対象外です。
- **一覧のタグは `selectedTag` で絞り込むこと**: カード・コンパクト行のタグを押したときは `filters.selectedTag` を設定します（クイックフィルターのタグチップ・統計ページの `/?tag=` と同じ条件）。`search` へ入れると名前やコメントにその語を含む記録まで一致し、チップにも「タグ」として表示されません。
- **登録フォームは区切りごとに並べること**: `VisitFormView` は `FormSection`（`section` + `h3`）で「場所」（地点検索・サウナ名・エリア）→「記録の内容」（ステータス・保存のしかた・日付・満足度・感想・写真）→「タグ」→「これまでの訪問」（編集時のみ、折りたたみの `VisitHistorySection`）の順に並べます。必須のサウナ名を場所の直後に置き、ステータスで出し分ける項目は「記録の内容」の中に閉じ込めてください。編集時の「新しい訪問を追加／前回の記録を修正」は排他の 2 択なので、チェックボックスではなく `.segmented` の切り替え（`HistoryAppendField`）で示します。満足度は選んでいる星をもう一度押すと 0 に戻し、別の「クリア」ボタンは置きません（下の星を押したときは外さずに選び直す）。満足度は 1 つの値を選ぶ操作なので `role="radiogroup"` ＋ `role="radio"`（`aria-checked` は選んだ星だけ）で公開し、矢印キーで上げ下げします。`aria-pressed` のトグルに戻すと、★4 のとき 1〜4 つ星がすべて「押されている」と読み上げられます。「保存のしかた」は保存済みのステータスが「行った」の記録だけに出します（`VisitFormView` の `editingStatus`）。行きたい記録には訪問が無いため、行ったへ切り替えたときは履歴の末尾を書き換えます（追加させると訪問回数が 2 から始まります）。
- **保存ボタンは入力不足なら押せる状態で案内すること**: 場所・サウナ名が足りないとき（`utils/form.ts` の `getSubmitFixTarget()`）は `disabled` ではなく `aria-disabled` にし、押されたら送信せずに足りない箇所へ案内します（場所はフォームを先頭へ戻して `.location-status.is-attention` で強調、サウナ名は入力欄へフォーカス）。`disabled` は保存中・画像処理中のように待つしかないときだけに使ってください。`disabled` に戻すと、押しても何も起きず、どこを直せばよいかがフォーム下端の小さな補足でしか伝わりません。場所の未選択は、フォーム先頭の `.location-status` が同じ文で示しているため、保存ボタン下の理由（`#submit-blocked-reason`）は `FormActions` の `hideBlockedReason` で `.sr-only` にし、読み上げ（`aria-describedby`）にだけ残します（見える形で出すと同じ案内が 2 つ、デスクトップでは地図側の `MobilePinHint` と合わせて 3 つ並びます）。サウナ名の不足や保存中・画像処理中の理由は見える形で出します。
- **再訪は「また行った」から記録できること**: 一覧カード（選択時）・コンパクト行（展開時）・地図ポップアップに `components/common/RevisitButton.tsx` を置き、`onEdit(visit, { revisit: true })`（`EditVisitHandler`）で編集を開きます。`useVisitFormState` の `startEditing` は `revisit` のとき `utils/form.ts` の `toRevisitFormState()` で、今日の日付・空の感想と評価・「新しい訪問を追加」の状態にします（行きたい記録は「行った！」の表示で、行ったへ切り替えて履歴の末尾を書き換えます）。地図ポップアップで塗りのボタンにするのは「また行った」だけで、編集は枠線だけの補助の操作にします。
- **地図で選んだ場所からエリアを補うこと**: `hooks/useAreaFromLocation.ts` が新規登録中（`editingId` が無い）かつエリア欄が空のあいだだけ、場所の選択から `AREA_LOOKUP_DELAY_MS`（1 秒）待って `utils/geocoding.ts` の `reverseGeocodeArea()` を呼び、「都道府県＋市区町村」を入れます。続けて場所を選び直したときは最後の 1 回だけ送り（公共 Nominatim の 1 秒 1 回の方針）、利用者がエリアを入力し始めたら待機中の問い合わせを取り消します。既存の記録を開いただけでエリアを書き換えないこと（意図しない変更が保存されます）。逆ジオコーディングの接続先は `NEXT_PUBLIC_GEOCODING_ENDPOINT` の `/search` を `/reverse` に置き換えて導き、`/search` で終わらない接続先では行いません。
- **タグの候補は `getTagSuggestions()` から**: フォームのタグ候補は `utils/visitStats.ts` の `getTagSuggestions()` が、利用者がよく付けるタグを先に、足りない分を `PRESET_TAGS` で `TAG_SUGGESTION_LIMIT` 件まで埋めます（「行きたい」は除外）。`VisitForm` コンテナが `useVisitsData()` から計算して `VisitFormView` の `suggestedTags` へ渡します。入力値の Context とは別なので、1 文字入力ごとに再計算されることはありません。
- **地点検索は明示操作だけで実行すること**: 公共Nominatimはクライアント側オートコンプリートを許可していないため、`LocationSearchInput`は検索ボタンまたはEnterでだけ`searchLocation()`を呼びます。入力変更のデバウンス検索へ戻さず、1秒のクールダウンと同一語句のメモリキャッシュを維持してください。Nominatim互換の接続先は`NEXT_PUBLIC_GEOCODING_ENDPOINT`で差し替えられます。
- **`searchLocation()` に `User-Agent` を付けないこと**: Fetch 仕様の禁止ヘッダ名でブラウザが必ず落とすため、指定してもアプリ識別にはなりません（Nominatim へは Referer が送られます）。
- **地点検索の障害を0件として扱わないこと**: `searchLocation()` は入力キャンセル (`AbortError`) だけ空配列へ変換し、HTTP・通信・JSONエラーと配列でない応答は呼び出し側へ再送出します。応答は zod（`NominatimRawResultSchema`）で検証し、座標が範囲内の数値にならない結果だけを除外します（`NaN` の座標を地図へ渡すと Leaflet が例外を投げます）。型注釈だけで信用する形へ戻さないでください。`LocationSearchInput` が通信障害用のエラー表示を出すため、一般エラーを握り潰して空配列へ戻さないでください。
- **訪問回数の算出**: 訪問回数は必ず `utils/visitHistory.ts` の `getVisitCount()` を使うこと（`history.length` と `visitCount` の両方を考慮します）。地図側と統計ページで別々に導出すると、旧形式データで表示が食い違います。訪問回数による順位付けは `utils/visitStats.ts` の `rankVisitsByCount()` に集約しています（同数のときの並びまで揃わないと、「MY HOME SAUNA」と「よく行く施設 TOP 5」で 1 位が食い違います）。
- **`utils/` 内のファイル同士は個別ファイルから import すること**: `utils/index.ts` は全ファイルを再エクスポートしているため、`utils/` 内から `"../utils"` 経由で読むと循環 import になり、読み込み順によっては値が `undefined` になります（`visitHistory.ts` が `./date` を読むのと同じ形にすること）。
- **最新履歴の本体への写しは 1 か所で行うこと**: 記録本体の `date` / `comment` / `rating` / `image` は履歴の末尾の写しです。履歴を足す・直す・消すどの経路でも `utils/visitHistory.ts` の `syncLatestFromHistory()` を通してください（`createNewVisit()` / `buildHistoryUpdate()` / `normalizeVisits()` / `getVisitsWithRemovedHistory()` がこれを共有します）。フォームから履歴 1 件を作る処理も `buildHistoryEntry()` に集約しており、新規作成と更新で日付・評価の既定値を食い違わせないこと。経路ごとに `history[history.length - 1]` から書き写すと、1 か所の直し忘れで一覧に出る本体の値と履歴の中身がずれます。訪問回数は第 2 引数で渡し、履歴を削除する経路だけ渡さない（残件数へ揃える）という区別も同関数に集約しています。
- **コンパクト行は施設名を 1 行目に単独で置くこと**: `VisitCompactItem` の 1 行目は施設名（`.sauna-compact-title`、`display: block` で省略記号を出す）だけにし、エリアと「N回 · 最終 日付」は 2 行目の `.sauna-compact-meta` に置きます。エリアを施設名と同じ行へ戻すと、縮まないエリアに押されて施設名がほとんど読めなくなります。2 行目で省略するのはエリアだけです（回数・日付は縮めない）。行きたい記録も同じ 2 行構成（`WishlistChip compact` ＋ エリア）にして行の高さを揃えます。
- **一覧のタグは `getDisplayTags()` を通すこと**: 行きたい記録は状態を `WishlistChip` で示すため、`utils/visitStatus.ts` の `getDisplayTags()` が同名の「行きたい」タグを表示から外します（保存値は変えません）。`visit.tags` をそのまま渡すと「行きたい」が 2 回並びます。チップの文言は同ファイルの `WISHLIST_LABEL` が唯一の出所です。
- **地図の初期表示は記録の範囲に合わせること**: `MapContainer` の `center` / `zoom` は読み込み前の仮の値です。`InitialViewFitter` が最初に記録が読み込まれたときに 1 回だけ、全件（絞り込み前の `useVisitsData().visits`）が見える範囲へ `fitBounds` します。範囲はサイドバー（デスクトップ）とボトムシート・下部ナビ（モバイル）に覆われた分を `components/map/mapInsets.ts` の `getCoveredWidth()` / `getCoveredHeight()` で余白に足します。絞り込み後の記録で範囲を決めると「表示範囲内だけ」の絞り込みと循環するため使わないこと。ディープリンク（`/?id=`）で移動する予定があるときは `skip` で合わせません。記録の追加や再読み込みのたびに合わせ直すと、利用者が動かした地図が勝手に戻ります。
- **行きたいの記録もクラスタにまとめること**: `VisitMarkers` は選択中・編集中の記録だけをクラスタの外に置きます。行きたいの記録まで外に置くと、同じ地域のクラスタの上に星のピンが重なって件数が読めなくなります。行きたいを含むクラスタは `createCustomClusterIcon` が右上に緑の星（`.sauna-cluster-wishlist`）を付けます。判定は子のマーカーのアイコンから `markerIcon.ts` の `isWishlistIcon()` で行い（クラスタのアイコンは記録ではなく `L.Marker` しか受け取れない）、アイコンのキャッシュのキーにも有無を含めます。
- **選択時のズームは `SELECT_ZOOM`（13）**: `MapController` は一覧・ピンから選んだ記録へ `SELECT_ZOOM` まで寄せます（それより拡大していれば縮小しない）。14 以上（街区）まで寄ると周囲に他の記録が無く、どこにいるのか分からなくなります。モバイルのボトムシート分の緯度オフセットはズーム 14 で 0.0045 を基準に、ズームが 1 段上がるごとに半分にしています（画面上で同じ距離になるように）。
- **新規登録で選んだ場所が画面外なら地図を移動すること**: `SelectedLocationFocus` は `selectedLocation` が表示範囲の外にあるときだけ `flyTo` します（地点検索で選んだ場所）。地図をタップして選んだ場所は範囲内なので動かしません（タップのたびに動くと位置を微調整できない）。
- **モバイルの場所選択中も地点検索を出すこと**: `SaunaMap.tsx` の `MobileLocationPickHint` が `MobilePinHint` に `onSelectSearchResult` を渡し、案内バーの下に `LocationSearchInput` を出します（候補は画面下端から上へ開く）。選んだ結果は登録フォームの検索欄と同じ `utils/form.ts` の `fillFormFromPlace()` でサウナ名・エリアを補い、`handleLocationSelect()` で場所を確定してフォームへ進みます。入力中のフォーム値（`useSaunaEditorForm`）を購読するため、`SaunaMapContent` で直接呼ばず、この小さなコンポーネントに閉じ込めてください。ライブリージョン（`role="status"`）は案内の文言（`.pin-hint-main`）だけに付けます。
- **一覧の表示形式は画面幅ごとに覚えること**: `VisitListView` はリスト／カードの選択をデスクトップ（`sauna_itta_view_mode`）とモバイル（`sauna_itta_view_mode_mobile`）で別々に保存します。共有すると、デスクトップで選んだカード表示のままモバイルで開いたときに、半分の位置のシートへ 1 件目の見出しすら収まりません。
- **デスクトップの地図移動はサイドバーの幅を差し引くこと**: `MapController` は選択した記録へ `flyTo` するとき、開いている `.sidebar` が地図を覆っている幅（`mapInsets.ts` の `getCoveredWidth()`）の半分だけ中心を左へずらし、マーカーを見えている領域の中央へ置きます（折りたたみ中・モバイル・地図の半分以上を覆う狭い画面ではずらしません）。モバイルのボトムシート分の緯度オフセットとは別の処理です。
- **訪問リストの行コンポーネント**: `VisitCompactItem` / `VisitCardItem` は表示密度が違うだけなので、props 型と `memo` の比較関数は `components/list/visitItem.ts` の `VisitItemProps` / `areVisitItemPropsEqual` を共有します。片方にだけ props を足すと比較関数の更新漏れで表示が古いまま残るため、個別に再定義しないこと。
- **テーマフックは 1 本**: 地図側・統計ページとも `hooks/useTheme.ts` を使います。統計ページのように静的プリレンダリングされる画面は `useTheme({ deferred: true })` で開始し、他のクライアント専用初期化と同じタイミングで `syncFromStorage()` を呼ぶこと（マウント直後に既定値でクラスを適用すると、`layout.tsx` のインラインスクリプトが付けた `light-theme` を剥がしてちらつきます）。
- **タグ集計**: タグの出現回数は `utils/visitStats.ts` の `countTags()` に集約しています（`getPopularTags()` はその薄いラッパー）。コンポーネント内で `visit.tags` を数え直さないこと。
- **訪問コメント**: コメントの表示は `components/common/VisitComment.tsx` の `VisitComment` 経由にすること（一覧カード・コンパクト行・地図ポップアップ共通）。3 行で省略し、実際にあふれたときだけ「続きを読む」（`aria-expanded`）を出します。CSS の `line-clamp` だけで切ると全文が編集画面でしか読めなくなり、省略しないとポップアップが地図を覆います。空のコメントは何も描画しません。
- **写真プレビュー**: 写真の拡大は必ず `components/common/VisitImagePreview.tsx` の `VisitImagePreview` 経由にすること（素の `img` に `onClick` を付けるとキーボードから開けません）。同コンポーネントは sanitize 済みの `src` を受け取るため、`sanitizeImageUrl()` の呼び出しは各コンポーネントで 1 レンダーにつき 1 回だけにします。
- **`data:` URL を URL パーサへ通さないこと**: 画像は最大 1MB の Base64 として保持されるため、`sanitizeImageUrl()` は `data:` を先頭の正規表現だけで判定し、`new URL()` は http(s)・相対パスの検証にのみ使います（40 件 × 1MB で 23ms → 0.01ms）。一覧の各行がレンダーのたびに呼ぶ関数なので、ここに文字列全体を走査する処理を足さないこと。SVG はスクリプトを埋め込めるため `SAFE_DATA_IMAGE` から意図的に除外しています。
- **アップロードの許可形式と表示の許可形式を混同しないこと**: 受け付ける形式は `utils/apiLimits.json` の `allowedImageMimeTypes`（`utils/image.ts` の `ALLOWED_IMAGE_MIME_TYPES` として公開）が唯一の出所で、`<input accept>`（`IMAGE_INPUT_ACCEPT`）と `useVisitFormState` の取り込み判定（`isAllowedImageFile`）の両方がここから導かれます。バックエンドの `VisitHistoryEntry::ALLOWED_IMAGE_TYPES` との一致は Rails の `test/contract/frontend_api_limits_test.rb` が検査します（`accept="image/*"` へ戻すと、apiモードではフォームを全部埋めて保存した時点で初めて「画像形式が許可されていません。」と弾かれます）。accept 属性はドラッグ&ドロップに効かないため、`handleImageFile` 側の判定を省かないでください。一方 `SAFE_DATA_IMAGE` は「すでに保存されている値を描画してよいか」の判定で、過去の版が受け付けた `image/jpg` / `image/bmp` の記録を表示し続けるために意図的に広く取っています。新しく保存できる形式を変えるときは `apiLimits.json` と Rails 側の定数だけを変えること。
- **グラフ**: Recharts の配色・ツールチップは `components/charts/chartTheme.ts` の `getChartColors()` / `getTooltipStyle()` を、空データ表示は `ChartEmptyState` を使うこと。チャート側でテーマ別の色分岐を直書きしないでください。ツールチップだけに具体値を置かず、チャートと兄弟の `.sr-only` テーブルにも全データを出し、キーボード・支援技術から月別件数や評価別件数を取得できる状態を保つこと（`role="img"` の内側へ表を置くと子要素が読み上げ対象から外れます）。
- **統計ページの履歴平坦化は 1 回だけ**: 訪問履歴の平坦化（`flattenVisitHistory()`）と `status === "visited"` の絞り込みは `useStatsData` の `visitedEntries` に集約しています。グラフやカレンダーは `visits` ではなく `FlatVisitHistoryEntry[]` を props で受け取ること。コンポーネントごとに `flattenVisitHistory(visits)` を呼ぶと、同じ走査を記録件数 × グラフ数だけ繰り返します。
- **統計ページの順位付けも 1 回だけ**: `rankVisitsByCount()` の呼び出しは `useStatsData` の `rankedVisits` に集約しています。`HomeSaunaCard` / `TopSaunasCard` は `visits` ではなく `RankedVisit[]` を props で受け取ること（カードごとに呼ぶと同じ絞り込みと並べ替えを繰り返します）。
- **月別件数は 0 件の月も埋めること**: 月別訪問数のグラフは `utils/visitStats.ts` の `getMonthlyVisitCounts()` を使い、最初の訪問月から最後の訪問月まで 0 件の月も並べます。記録のある月だけを並べると、x 軸が飛んでも等間隔に見えて空白期間が読めなくなります。
- **都道府県が判定できないときは 0 と出さないこと**: サマリーの「都道府県制覇」は `prefectureCount` が 0 のとき数値の代わりに「-」と補足を出します（エリアが地名だけだと常に 0 になり、「1 つも行っていない」と読めてしまうため）。
- **都道府県制覇は 47 都道府県を北から南の順にすべて並べること**: 並び順は `utils/geo.ts` の `PREFECTURES`（JIS の都道府県コード順）が唯一の出所で、`calculateStats()` の `prefectures` も `comparePrefectures()` で同じ順に並べます。`PrefectureSection` は行った都道府県を塗り、未訪問は破線の枠だけで同じ位置に出し、制覇率を `role="progressbar"` で示します。五十音順や行った都道府県だけの表示へ戻すと、どの地方が残っているかが読めません。一覧に無い名前（エリアの表記揺れ）は行ったものとして末尾に残します。
- **都道府県制覇は広い画面で日本地図の形に並べること**: `PrefectureSection` は同じ `ul`（読み上げの順は北から南のまま）を、1024px 以上だけ 14 列の grid にして各 `li` の `style`（`gridColumn` / `gridRow`）で `utils/geo.ts` の `PREFECTURE_TILES` の位置に置きます。マスに収まらない「県・府・都」は `splitPrefectureSuffix()` で分けて `.prefectureSuffix` に入れ、見た目だけ隠します（`display: none` にすると読み上げからも消えます）。狭い画面は従来のチップの並びです。横に `PREFECTURE_REGIONS`（8 地方）ごとの制覇数を並べます。配置を変えるときは `geo.test.ts` の「重ならない位置」の検査を通してください。
- **一覧カードは選んだときだけ経路と「また行った」を出すこと**: `VisitCardItem` の `.sauna-card-footer-actions` は `isSelected` のときだけ描画します（コンパクト行の展開時と同じ）。全カードに枠線のボタンが 2 つずつ並ぶと、一覧の大半がボタンの列になって記録の中身が埋もれます。エリアと満足度は `.sauna-card-summary` の 1 行にまとめ、狭い幅ではエリアだけを省略します。
- **統計画面は年で絞り込めること**: `useStatsData` は読み込んだ記録（`allVisits`）を `utils/visitStats.ts` の `filterVisitsByYear()` で選んだ年に絞り込んでから、サマリー・平坦化・順位付けのすべてへ渡します（一部だけ全期間のままにすると、同じ画面の数字同士が食い違います）。行った記録はその年の履歴だけに作り直し（`syncLatestFromHistory()` で本体の値も揃え、旧形式の `visitCount` は数えない）、その年に行っていない記録は除きます。行きたい記録は期間に関係しないため残します。年の選択肢は `getVisitYears()`（新しい順）で、`YearFilter`（`role="group"` ＋ `aria-pressed`、年が 1 つだけなら描画しない）がヘッダーの直下に出します。記録が読み込み直されて選んでいた年が無くなったときは全期間へ戻します。
- **統計画面の並びはサマリー → 訪問カレンダー → ホームサウナ・TOP 5 → グラフ → タグ → 都道府県**: いつ・どれくらいの頻度で行ったかを示すヒートマップを最下部に置くと読まれないため、サマリーの直後に置いています。
- **訪問カレンダーのカードには年間ヒートマップを並べること**: `VisitCalendar` はカードの上に `VisitHeatmap`（直近 53 週、最後に訪問した日を含む週が右端。年を選んでいるときはその年の大みそかを含む週が右端で、見出しも「N年は」。ただし今年は先の空白の週を並べないよう最後に訪問した日のまま）をカード幅いっぱいに、下に月のカレンダーを置きます。マスの組み立ては `utils/visitHeatmap.ts` の `buildVisitHeatmap()`、最新の訪問日は `getLatestVisitDate()`（カレンダーの初期月と共有）です。マスは見た目用（`aria-hidden`）で、読み上げには期間と訪問日数の要約を `role="img"` の `aria-label` で渡します。段階のクラス名はテンプレートリテラルで組み立てず、参照表（`LEVEL_CLASS`）から引くこと（`tokens.test.ts` のクラス名検査が追えなくなる）。マスの大きさは CSS のローカル変数を使わず固定値で書きます（`tokens.test.ts` は `base.css` に無い変数を未定義として扱う）。
- **訪問カレンダーの横に月の訪問一覧を並べること**: `VisitCalendar` はヒートマップの下の段（`.calendarBody`、860px 以上で 2 列）にカレンダーと `MonthVisitList` を並べます。一覧は表示中の月（`onActiveStartDateChange` の `view === "month"` のときだけ更新し、年の表示へ切り替えても前の月のまま）の訪問を `utils/visitStats.ts` の `getVisitEntriesInMonth()` で日付順に出し、日を選ぶとその日の訪問だけに絞り込みます（「N月の訪問をすべて表示」で戻す）。選んだ日はローカル state（`pickedDay`）で持ち、`date` では判定しないこと（初期値が今日のため、選んでいなくても絞り込まれます）。カレンダーには `locale="ja-JP"` を指定します（未指定だとブラウザの言語に従い、英語環境では「August 2025」「SUN MON」になります）。カレンダーの表示位置（`activeStartDate`）は制御しているため、年・10 年の表示への切り替えでも必ず更新してください（月の表示だけで更新すると、年の表示で前後へ移れなくなります）。
- **月別訪問数の目盛りは月の数で刻みを決めること**: `MonthlyVisitsChart` は `getMonthTicks()`（6 か月以内は毎月、12 か月以内は 2 か月、36 か月以内は 3 か月、72 か月以内は 6 か月、それ以上は 1 月だけ。1 月を起点に揃える）を `ticks` に渡し、目盛りは `formatMonthTick()` の「3月」の形にします（年は年の境目の縦線のラベルが示す）。Recharts の自動の間引きに戻すと「2024-03, 2024-06, 2024-09, 2024-11」のように間隔が不揃いになります。
- **訪問カレンダーの初期表示は最後に訪問した月**: `VisitCalendar` は表示位置（`activeStartDate` の state の初期値）を `visitDates` の最新日の月に合わせます。年を切り替えたときに開き直すよう、`page.tsx` は `key` に年を渡して作り直します。今月を開くと、今月に訪問が無い利用者には空のカレンダーが表示されます。
- **訪問回数の順位は 2 回以上行った施設だけで付けること**: どの施設も 1 回ずつのときに訪問回数で並べると、全員同率で五十音順の先頭が「1 位」になるだけです。`utils/visitStats.ts` の `REPEAT_VISIT_MIN_COUNT`（2）を境に、`HomeSaunaCard` は条件を伝える案内に切り替え（カードを消すと TOP 5 と並ぶ 2 列の片側が空くため）、`TopSaunasCard` は `getRepeatVisits()` の施設だけを並べ、1 つも無いときは `sortRankedByRating()` の満足度順（見出しも「満足度の高い施設 TOP 5」、回数とバーは出さない）に切り替えます。
- **MY HOME SAUNA のカードは日付の行を下端に寄せること**: `HomeSaunaCard` は右隣の TOP 5 と高さが揃うため、`justify-content: space-between` で縦に散らすと施設名と割合のバーの間が大きく空きます。上から詰めて並べ、最新の感想（`.homeSaunaComment`、2 行で省略）を添え、初訪問・最新訪問の行（`.homeSaunaFooter`）だけを `margin-top: auto` で下端に置きます。日付は `formatShortDate()` ＋ `<time dateTime>` で表示します。
- **統計画面の空状態は `StatsEmptyState` を使うこと**: 記録が 0 件のときは `variant="none"`、行きたいだけ（`stats.visitedCount === 0`）のときは `variant="wishlistOnly"` を出します。グラフ・ランキング・カレンダーは行った記録だけから集計するため、行きたいだけのときは空のカードを並べず、空状態＋サマリー＋タグクラウドだけにします。構成は地図側の `VisitListEmpty` と同じ「アイコン＋見出し＋説明＋操作」に揃えます。
- **タグクラウドは先頭だけを出すこと**: `TagCloudCard` は件数の多い順に `TAG_CLOUD_INITIAL_COUNT` 件だけを表示し、残りは「すべて表示」（`aria-expanded` / `aria-controls`）で開きます。全種類を並べると 100 件を超える同じ大きさのチップの壁になり、よく使うタグが埋もれます。1 回しか付いていないタグは `.tagPillRare` で控えめにします。
- **満足度の配色は順序のある段階色にすること**: ★1〜★5 の色は `chartTheme.ts` の `getChartColors(theme).rating` から取り、色相を変えずアプリのアンバーの明るさ・彩度の段階で並べます（ダークは高い評価ほど明るく、ライトは高い評価ほど濃く。`chartTheme.test.ts` が輝度の順を検査します）。緑・青・赤のように色相で分けると、どれが高い評価なのかを凡例を見ないと読めません。チャート側に色を直書きしないこと。
- **満足度分布は凡例を出すこと**: `RatingDistributionChart` はドーナツの横に ★5〜★1 の件数と割合の凡例を並べます（0 件の評価も薄く表示）。色だけでは何点の割合か読み取れません。凡例は見た目用（`aria-hidden`）で、読み上げは兄弟の `.sr-only` テーブルが担います。
- **記録期間は長さを主の値にすること**: サマリーの「記録期間」は他のカードと同じ「大きな数値＋単位」の形で `SummaryGrid` の `formatPeriodLength()`（始まりと終わりの月を含めた「N ヶ月」「N 年 M ヶ月」）を出し、範囲は下の `.statNote` に `YYYY.MM 〜 YYYY.MM`、日単位の期間は `title` と `<time dateTime>` に残します。範囲そのものを主の値にすると、このカードだけ小さな文字で 2 行に折り返し、サマリーの文字の大きさと高さが揃いません。サマリーの見出しも 1 行に収まる短さにします。施設のカードは見出しを「行った施設」、値を行った施設の数にし、行きたいの件数は `.statNote` の「ほかに行きたい N 件」に回します（「施設数 97 行った / 2 行きたい」の形に戻すと、97 が何の数かを読み取りにくくなります）。`.statCard` は値を見出しの直後に置く（`justify-content: flex-start`）こと。`space-between` に戻すと、補足の無いカードだけ値が下端へ寄り、同じ行で数字の高さが揃いません。
- **同じ数字を 2 か所で計算しないこと**: 平均満足度は `calculateStats()` の `stats.avgRating` が唯一の出所で、`RatingDistributionChart` は `avgRating` を props で受け取って表示します（グラフ側で再計算すると、サマリーと中央表示の数字がいずれ食い違います）。

## 3. パフォーマンス
- 訪問リスト（`VisitList.tsx`）は全件を一度に描画せず、`INITIAL_RENDER_COUNT` 件から `IntersectionObserver` で `CHUNK_SIZE` ずつ描画を伸ばす増分レンダリング方式です。描画件数は state ではなくレンダー中に導出しているため、`useEffect` 内で `setState` を呼ぶ実装（React Compiler / `react-hooks/set-state-in-effect` に抵触）へ戻さないでください。
