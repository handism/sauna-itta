# フロントエンド規約（CSS ＆ アクセシビリティ）

このファイルは `frontend/src/` 配下を編集するときに読み込まれます。状態管理・コンポーネント構造の規約は `frontend/src/components/sauna-map/AGENTS.md`、全体方針はリポジトリルートの `AGENTS.md` を参照してください。

## 1. CSS ＆ スタイリング
- Z-Index や共通カラー変数等のレイアウト値は `styles/base.css` 内の CSS デザイントークンを必ず参照・利用してください。
- **未定義トークンの禁止**: `var(--foo)` を書く際は `base.css` に定義があるか必ず確認すること（未定義変数は無言で無効化され、背景が透明になる等の不具合になります）。`var(--foo, #hex)` のようなフォールバックは書かないこと（未定義を隠すうえ、ダーク固定色がライトテーマに漏れます）。
- **重ね色は必ずトークン経由**: 面の上に薄く重ねる色（カード背景・ホバー等）に `rgba(255, 255, 255, ...)` を直書きすると、ライトテーマで白地に白が乗って消えます。`--overlay-subtle` / `--overlay-hover` を使うこと。同様に、`--glass-hover` はライトテーマでほぼ白になるため、その上に `color: #fff` を固定しないこと。
- **エラー色**: 面には `--error`、文字色には `--error-text` を使うこと（`--error` をそのまま小さな文字に使うとライトテーマでコントラスト比 4.5:1 を下回ります）。
- **色トークンは `:root` と `.light-theme` の両方に定義すること**: 片方だけに定義すると、ダーク前提の濃い色がライトテーマへそのまま漏れます（`--secondary` の濃紺がライトのサイドバーに乗る、`--star-color` が白地で 1.8:1 になる等）。意図的に共有する場合は `styles/tokens.test.ts` の `SHARED_ON_PURPOSE` に理由付きで追記します。グラデーションの 2 色目のようなペアの色も直書きせずトークン化すること（`--accent-water-deep` / `--accent-wishlist-deep`）。
- **文字サイズは `--text-*` トークンを使うこと**: `font-size` は `base.css` の `--text-xs`（12px）〜`--text-3xl`（24px）の 7 段階（12/13/14/16/18/20/24px）から選びます。以前の 0.05rem 刻みの段階（`--text-2xs` / `--text-base`）は隣と見分けが付かなかったため廃止しました。日本語は 12px を下回ると潰れるため、`--text-xs` より小さい段階を足さないでください。`0.78rem` / `0.82rem` のような直書きを増やすと、見出し・本文・補足の強弱が画面ごとにずれていきます。`styles/tokens.test.ts` が地図・統計の CSS を検査しており、例外（マーカーの 10px、Leaflet の閉じるボタンの 22px、iOS の拡大を防ぐ入力欄の 16px、見出しの `clamp()`）は同テストの `ALLOWED_LITERALS` に理由付きで置いています。インラインスタイルでも `fontSize: "var(--text-md)"` のようにトークンを使ってください（Recharts の SVG 目盛りの数値指定は対象外）。
- **太さは 400 / 600 / 700 の 3 段階だけにすること**: 500 や 800 は日本語の OS フォントで隣の太さと見分けが付かないか、近い太さへ丸められます。`styles/tokens.test.ts` が地図・統計の CSS を検査しています（インラインスタイルの `fontWeight` も同じ 3 段階にしてください）。
- **影は `--shadow-*` トークンを使うこと**: `box-shadow` に `rgba(0, 0, 0, ...)` を直書きすると、ライトテーマで明るい背景に濃い黒の影が落ちます。面の浮き上がりは `--shadow-sm` → `--shadow-md` → `--shadow-lg` → `--shadow-xl`、画面下端からせり上がる面（ボトムシート等）は `--shadow-up` を使います。**地図上のマーカー・クラスタだけは `--shadow-marker-sm` / `--shadow-marker` / `--shadow-marker-lifted`** を使うこと（これらは両テーマ共通です。ライトで弱めると地図タイルに溶けて位置が読めなくなります）。`--primary-glow` などの発光は影トークンの後ろに並べて追加します。
- **クラス名の綴り**: CSS のクラス名がコンポーネント側に存在するかも `styles/tokens.test.ts` が検査します（`mobile-nav-icon-add` と `mobile-nav-icon--add` のような綴り違いは誰もエラーにしてくれず、スタイルが当たらないまま放置されるため）。テンプレートリテラルで修飾子を組み立てる場合は、同テストの `IGNORED_PREFIXES` に追記してください。条件付きのクラス名は `` `a ${cond ? "b" : ""}` `` ではなく `components/sauna-map/utils/classNames.ts` の `cx("a", cond && "b")` で組み立てます（条件が偽のときに空白が余らず、クラス名も丸ごと書くため同テストの検査から外れません）。
- **要素セレクタで文字色を一括指定しないこと**: 既定の文字色は `html`/`body` の `color` から継承させます。`span` / `div` にまで色を固定すると、色付きの面の中の子要素が親の色を継承できなくなり、「button の中身は span で構成する」方針と衝突します（`base.css` 末尾のコメント参照）。
- **トグルの活性クラス**は `is-active` に統一しています（`--active` 系の BEM 修飾子を新規に増やさないこと）。地図上のコントロールは `MapControlButton` の `active` prop に任せると `is-active` と `aria-pressed` が同時に付きます。
- 上記の CSS 規約は `styles/tokens.test.ts` が地図CSSに加えて統計画面の`stats.module.css`／`stats-shell.module.css`も静的検査しています。意図的な例外を追加する場合は、同テストの許可リストに理由付きで追記してください。統計画面のページ背景・ヘッダー・空状態は`stats-shell.module.css`、カードと可視化レイアウトは`stats.module.css`へ置き、再び単一の巨大ファイルへまとめないでください。
- **タッチターゲット**: 操作要素は最低 24px、モバイル（`max-width: 767px`）では 44px 以上を確保してください。44px 保証は各 CSS ファイル末尾の `@media (max-width: 767px)` ブロックにまとまっています（`bottom-sheet.css` = モバイルナビ、`visit-list.css` = 検索・並び順・チップ、`visit-form.css` = 入力とボタン、`visit-card.css` = カード・タグ・履歴削除、`modal.css` = モーダルとトースト、統計ページは `stats.module.css`／`stats-shell.module.css` の同じ `max-width: 767px` ブロック）。モバイル境界は全画面で `767px`（JS の `MOBILE_BREAKPOINT` = 768px 未満）に揃えます。画面ごとに別の値を使うと、同じ幅でも片方の画面だけ 44px 保証が外れます。内容幅の都合で別の `max-width` が必要な場合は、`styles/tokens.test.ts` の `CONTENT_BREAKPOINTS` に理由付きで追記してください。新しい操作要素を追加したら、既定サイズが小さいもの（アイコンのみのボタン、チップ等）を対応するブロックへ必ず追記すること。
- **静的カードにクリックの見た目を付けないこと**: 統計ページの `.glassCard` は情報表示用の共通面であり、カード自体には hover の浮上・強調を付けません。リンクやボタンを持つ場合は、その対話要素だけに hover / focus の反応を付け、カード全体がクリックできるように誤認させないでください。
- **横スクロールを隠さないこと**: クイックフィルターは横方向に項目が続くため、スクロールバーを完全に非表示にせず `scrollbar-width: thin` を維持します。候補が多い場合はモバイルで `.quick-filter-scroll-hint`（矢印アイコンだけ）を表示し、横スワイプ可能であることを視覚的に伝えてください。案内に「横にスワイプ」のような文字を戻さないこと（右端のチップに重なり、隠れたチップのアイコンと並んでそういう名前のチップに読めます）。案内はチップ列の右端にフェードで重ねる配置（`position: absolute` + `pointer-events: none`）にし、独立した行へ戻さないこと（1 行ぶんの高さを取ると、半分の位置のボトムシートで一覧が 1 件も見えなくなります）。デスクトップでは矢印の案内も出さず、`.quick-filter-container::after` のフェードだけで続きがあることを示します。スクロールバーとチップの間に余白（`.quick-filter-chips` の `margin-bottom`）を足すと、バーが宙に浮いた灰色の棒に見えるため、下の余白は `.quick-filter-container` 側だけに持たせてください。
- **モバイルの一覧は半分の位置でも記録が見えること**: `.bottom-sheet--half` の高さ（60vh）と、一覧上部の操作部（見出し・検索・ステータス／並び順・チップ）の余白は、半分の位置で記録が数件見えるように調整しています。操作部へ行を足す場合は、モバイルでの高さを確認し、表示切替のようにアイコンだけへ畳めないか検討してください（`.view-mode-label` はモバイルで非表示、読み上げは `aria-label` が担当）。
- **スクロール領域の下端に固定する要素**: フォームの `.form-actions` はスクロール領域（`.sidebar-content` / `.bottom-sheet-content`）の下端に `position: sticky` で固定し、`bottom` を各領域の `padding-bottom` ぶん負にしています。どちらかの余白を変えるときは `visit-form.css` の `bottom` も揃えてください（ずれると隙間から後ろの入力欄が透けます）。背景は `--glass-heavy` の下に `--background` を敷いて不透明にしています。
- **一覧行の編集ボタン**: コンパクト表示の編集ボタンは、`(hover: hover)` かつデスクトップ幅のときだけ行のホバー・選択・`:focus-within` で現れます。`display: none` で隠すと Tab で到達できなくなるため `opacity` で隠すこと。タッチ端末では常に表示します。
- **主役の操作だけ塗りのボタンにすること**: サイドバーヘッダーのアイコンボタンのうち、新規登録だけ `.sidebar-action-btn--primary` で塗りにしています。同じ見た目のボタンを増やすと何から始めればよいかが伝わらなくなるため、他の操作には付けないでください。記録の入力中（新規・編集）もこのボタンは消さずに `disabled` で残し、中立色の面にします（消すと右側のボタンが左へ詰まり、フォームを開くたびにヘッダーの配置がずれます）。押せない `.btn-primary`（`disabled` / `aria-disabled`）と地点検索の `.location-search-submit:disabled` も、塗りを半透明にするのではなく中立色（`--overlay-hover` ＋ `--text-muted`）にしてください（くすんだ茶色の面に白文字が乗り、押せるのかどうかが読めません）。地図右上のクラスタ表示の切り替え（`.map-cluster-control-btn.is-active`）は既定でオンのため、オンの見た目はアイコンの色だけにします（面や枠まで塗ると、地図の操作の中で常にいちばん目立ちます）。登録フォームのステータス（`.segmented-btn--visited` / `--wishlist`）も塗りにせず、各色を薄く敷いた面＋枠で示します（塗りにすると、場所が未選択で保存ボタンが中立色のあいだ、フォームでいちばん目立つのがこの切り替えになります）。地図ポップアップでも塗りは「また行った」（`.revisit-btn--primary`）だけで、編集（`.popup-edit-btn`）は枠線のボタンです。一覧カード・コンパクト行の「また行った」は経路リンク（`.route-link`）と同じ形の枠線ボタン（`.revisit-btn`）にし、塗りにしないでください（カードごとに塗りのボタンが並ぶと一覧の主役が分からなくなります）。
- **地図タイルのフィルターはタイル 1 枚ずつに掛けること**: `--map-filter` は `map.css` の `.dark-map-tiles img.leaflet-tile` に掛けます。レイヤー（`.dark-map-tiles`）に掛けると leaflet.css の継ぎ目対策（`mix-blend-mode: plus-lighter`）が効かず、小数の devicePixelRatio（Pixel 7 の 2.625 等）でタイルの境目が格子状の線として見えます。
- **OSM の帰属表示を隠さないこと**: ライセンス上の必須表示です。モバイルでは `map.css` が `.map-wrapper:has(.bottom-sheet--min)` / `--half` のときに `.leaflet-bottom` をボトムシートの上端へ持ち上げています。シートの高さ（54px / 60vh）や下部ナビの高さ（56px）を変えるときは、この値も揃えてください。
- **ボトムシートの面は不透明にすること**: `.bottom-sheet` の背景は `--glass-heavy` の下に `--background` を敷いています（`.form-actions` と同じ）。`--glass-heavy` だけに戻すと、ぼかしが効かない環境で一覧の背後に地図のマーカーが透けます。
- **ダークテーマの地図**: `--map-filter` は OSM タイルを反転したうえで彩度を落とし（`saturate(20%)`）、マーカーが主役になるようにしています。彩度を戻すと緑の陸地・赤い道路がマーカーと競合します（40% でも街区まで拡大するとピンクの道路網がマーカーと競合したため、20% まで下げています）。
- **ライトテーマの地図も彩度を落とすこと**: ライトの `--map-filter` は反転せずに `saturate(45%)` 程度へ落としています。`none` に戻すと OSM の赤い幹線道路・濃い緑地がアンバーのクラスタと競合します。
- **一覧の検索欄と絞り込みの行はスクロールしても上端に残すこと**: `VisitListSearch` は検索欄とステータス・並び順の行を `.sauna-search-sticky`（`position: sticky`）に入れ、詳細フィルターとチップは下の `.sauna-search-box` に分けています。sticky は親要素の範囲内でしか効かないため、`.sauna-search-sticky` を包む要素を作らず一覧（`.sauna-list`）の直下に置くこと（包むと、その要素ごとスクロールで流れて固定されません）。`top` と左右の負のマージンはスクロール領域（`.sidebar-content` / `.bottom-sheet-content`）の余白に合わせているため、余白を変えるときは `visit-list.css` の値も揃えてください。詳細フィルターやチップまで固定に含めると、開いたときに固定部分が一覧の大半を覆います。
- **サイドバーのヘッダーは面の内側に収めること**: タイトル（`--text-2xl`）と操作 5 つを 420px の面の内側（約 367px）に並べており、余裕は数 px です。統計画面への入口だけは別画面へ移る操作なので「統計」の文字を添えています（`.sidebar-action-btn--labeled`、読み上げは先頭に「統計」を含む `aria-label`）。操作を足す・タイトルを大きくするときは、折りたたみボタンが面の外へはみ出さないか実ブラウザで確認してください。
- **サイドバーの折りたたみボタンはヘッダーの右端に置くこと**: 配置を変える補助の操作なので、主役の新規登録より先（左端・Tab の先頭）に置かないでください。
- **ボトムシートの件数は最小位置のときだけ出すこと**: 開いているときは一覧の見出しに「(N件)」があるため、`.bottom-sheet-summary-badge` の「N件表示中」は `min` のときだけ描画します（選択中の施設名は位置に関わらず出します）。
- **一覧の下端は面へ溶かすこと**: デスクトップの `.sidebar-content` は一覧（`.sauna-list`）を表示しているときだけ `mask-image` で下端 1.5rem をフェードし、最後の行が枠で切れて見えないようにしています。フォーム表示中は下端に保存ボタン（sticky の `.form-actions`）があるため、`:has(> .sauna-list)` の条件を外さないでください。
- **サイドバーの面は透かしすぎないこと**: `.sidebar` の背景は下側（`--secondary`）も 90% まで不透明にしています。半分程度まで透かすと、一覧の背後に地図の地名が透けて記録名が読みにくくなります。
- **モバイルの下部ナビは移動先と追加だけにすること**: `MobileNavBar` はマップ・一覧・追加・統計の 4 項目です。詳細フィルターは一覧の検索欄の横（`FilterToggleButton`、モバイルでも 44px）にあるため、パネルを開くだけの操作をナビへ戻さないでください（移動先の中に性質の違う項目が混ざり、各項目の幅も狭くなります）。
- **写真はカードとポップアップの先頭に置くこと**: 一覧カード（`VisitCardItem`）と地図ポップアップの `VisitImagePreview` は `className="sauna-img-preview-btn--cover"` を付けて先頭に置きます。コメントの下に戻すと、カードを読み進めないと写真の有無が分かりません。
- **「行きたい」のチップは星のアイコンにすること**: `WishlistChip` は地図の行きたいピンと同じ星を使います。タグのアイコンにすると、記録に付けたタグと同じ種類のものに見えます。
- **表示だけのタグはボタンにしないこと**: `VisitTagList` は `onSelectTag` を渡したときだけ絞り込みのボタン（`.sauna-tag-btn`）を描画し、渡さない場合（地図ポップアップ）は `span.sauna-tag` にします。押しても何も起きないボタンを置かないでください。
- **未評価の表示は中立色にすること**: `span.rating-unrated` は星の位置のクラス（`.sauna-card-rating` は `--star-color`）より詳細度を上げて `--text-muted` にしています。アンバーのままだと評価済みに見えます。
- **ピンの上のピルは左揃えにすること**: `.sauna-marker-badges` は縦並びの flex のため、`align-items: flex-start` を外すと短い「2回」のピルが「★4.0」の幅まで伸びます。ピルの色は地図タイル上の視認性を優先して両テーマ共通の `--marker-pill-*` トークンを使います（`tokens.test.ts` の `SHARED_ON_PURPOSE`）。
- **地図の拡大・縮小ボタンは 1 つのピルにつなげ、モバイルでも外さないこと**: `.map-zoom-control` は＋／−を 1 つの形にまとめ、影はピル全体に付けます。ピンチだけにすると指 1 本で縮小する手段が無くなります（WCAG 2.5.1）。
- **よく行く施設のピン**: 行った記録のうち `FREQUENT_VISIT_MIN_COUNT`（3 回）以上のピンは `.sauna-marker--frequent` で 40px・`--star-color` の縁取りにします。大きさを変えるときは `markerIcon.ts` の `iconSize` / `iconAnchor` / `popupAnchor` も同じ値に揃えること（ずれるとピンの先端が地点からずれます）。
- **選択の解除はエラー色にしないこと**: 一覧の「選択を解除」（カード）／「閉じる」（コンパクト行）の `.sauna-card-deselect-btn` は記録を消す操作ではないため、`--error` の赤ではなく中立色にしています。赤くすると削除や「行きたい」の解除と誤読されます。
- **タグの入力はチップにすること**: 登録フォームの `VisitTagsField` は、付けたタグを `.tag-input-chip`（×の `.tag-input-chip-remove` で外す）で並べ、入力欄（`#visit-tags`、ラベルは「タグを追加」）には次の 1 件だけを打ちます。Enter・「,」「，」「、」で確定し、空の入力欄の Backspace で最後のタグを外し、フォーカスが外れたとき（保存ボタンを押したときを含む）に確定し忘れた 1 件を拾います。変換中（`isComposing`）は区切らず、Enter でも確定・送信しないこと（IME の未確定文字列を壊します）。フォームの値は従来どおりカンマ区切りの `tagsText` で、確定前の 1 件はコンポーネントのローカル state に置きます（`tagsText` へ入れるとチップとして表示されます）。1 行のカンマ区切りテキストへ戻すと、全角の「、」で区切ったタグが 1 つにまとまって保存されます。
- **タグのチップは面と違う色にすること**: `.sauna-tag` は `--glass` のカードの上に乗るため、背景は `--overlay-subtle` ＋ `--glass-border` の枠線にしています。カードと同じ `--glass` に戻すとチップの形が見えず、折り返した行が字下げされた文字列のように見えます。
- **統計画面の見出しはモバイルで 1 行に収めること**: `StatsHeader` の「マップに戻る」はモバイルでアイコンだけにし（`.backLinkLabel` は見た目だけ隠して読み上げに残す）、`h1` には `word-break: keep-all` と `text-wrap: balance` を付けています。文字付きに戻すと 390px 幅で「統計ダッシュボー／ド」と 1 文字だけ折り返します。空状態の `.backLink` は文言だけの操作なので、アイコンだけにする指定は `.headerActions` の中に限ります。同じ理由で、TOP 5 の「地図で見る」もモバイルではピンのアイコンだけにしています（`.mapJumpLabel`）。
- **フォームの区切りの見出しは項目のラベルより強くすること**: `.form-section-title` は `--text-lg`・`--foreground` にしています。ラベル（`--text-md`、やや薄い色）より小さく薄い色にすると補足の文字に見え、区切りが読めません。
- **ヒートマップの 1 回の段階は空のマスとはっきり分けること**: 1 日 1 回の訪問が大半なので、ほとんどのマスは `.heatmapLevel1` になります。薄くすると（以前の 35%）ダークでは空のマスと見分けられません。
- **統計画面の react-calendar**: `calendar.css` の色は react-calendar 用の固定色ではなくアプリのトークン（`--foreground` / `--primary` 等）から取ります。選択中の日はアンバーの面に白文字だとコントラストが足りないため、薄い面＋枠線で示します。
- **フォント**: `--font-main` は `layout.tsx` の `next/font` (Outfit) が注入する `--font-outfit` を参照します。Outfit はラテン文字だけなので、日本語は後続の各 OS の日本語ゴシック（ヒラギノ／Noto Sans JP／Yu Gothic UI／メイリオ）で表示します。フォールバックから日本語書体を外すと Windows 等で旧来のゴシックに落ちるため削らないこと。日本語 Web フォントを `next/font` で同梱する場合も、サイズとビルド時のネットワーク取得を考慮してください。CSS からの Web フォント `@import` は追加しないでください（PWA のオフライン動作を壊します）。`outfit.variable` のクラスは `body` ではなく `<html>` に付けること（`--font-main` は `:root` で `var(--font-outfit)` を参照するため、`body` に付けると `:root` では未定義になり、`--font-main` ごと無効値になってブラウザ既定の書体へ落ちます。`layout.test.tsx` が検査しています）。地図のポップアップは leaflet.css の `.leaflet-container` の書体・`.leaflet-popup-content p` の余白・`.leaflet-container a` のリンク色が本アプリの CSS より後に読み込まれて勝つため、`map.css` で親クラスを付けて詳細度を上げて上書きしています。ポップアップに共通部品を足したときは、Leaflet 既定が漏れていないか実ブラウザで確認してください。
- **ヒートマップのマスは列幅に収めること**: `stats.module.css` の `.heatmapWeekdays` は `contain: size` で曜日の文字の高さを表の高さの計算から外し、幅を明示しています。外すと 12px の文字の行の高さ（約 24px）で表の高さが決まり、正方形のマス（`aspect-ratio: 1`）が列幅より広くなって隣の週へ重なります。`.heatmapWeek` の `grid-template-columns: minmax(0, 1fr)` も同じ理由で外さないこと。
- **react-calendar のボタンは書体を継承させること**: `calendar.css` の `.react-calendar button { font-family: inherit; }` を外すと、見出しの年月や日付がブラウザ既定の書体になります。曜日は日本語ロケールのため `text-transform: uppercase` は付けません。
- **新規登録のフォーム下端は 1 行にすること**: 削除ボタンの無い新規登録では、`.form-actions` を `:has(> .form-actions-secondary--single)` で 2 列の grid にし、保存とキャンセルを横に並べます（押せない理由は 2 行目に全幅）。縦に積むとボタンだけで約 120px を取り、固定した面が入力欄を覆います。
- **コンパクト行の操作ボタンの上余白は行の側に持たせること**: `.route-link` / `.revisit-btn` は単独で置くための `margin-top` を持つため、「閉じる」と並ぶ `.sauna-compact-footer-actions` の中では 0 にし、余白は行の `margin-top` にまとめています（戻すと「閉じる」だけが上にずれます）。
- **タッチ端末のコンパクト行の編集ボタンはアイコンだけにすること**: モバイルでは全行に常に出すため、`.sauna-card-edit-btn.compact-edit-btn` の面と枠を消し（押せる範囲は 44px のまま）、展開している行（`.is-selected`）だけ枠を戻します。詳細度を 2 クラスにしているのは、後から読み込まれる `visit-card.css` の `.sauna-card-edit-btn` に負けないためです。

## 2. アクセシビリティ ＆ モーション
- `base.css` のグローバル `:focus-visible` リングを維持してください。`outline: none` を書く際は代替の可視化を必ず用意すること。
- クリック可能な要素は `div` ではなく `button` / `a` を使い、`aria-expanded` / `aria-pressed` / `aria-current` で状態を公開すること。
- **対話要素を入れ子にしないこと**: 訪問リストの各行は、編集ボタン・タグ・経路リンクを内包するため行全体を `role="button"` にできません。開閉／選択のトグルは見出しの中のボタン（`<h3><button aria-expanded>`＝WAI-ARIA のアコーディオンパターン）とし、編集ボタンは必ずその**兄弟要素**に置きます（`VisitCompactItem` / `VisitCardItem` 参照）。`button` の子は phrasing content に限られるため、中身は `span` で構成してください。
- **`tablist` を絞り込みトグルに使わないこと**: 対応する `tabpanel` と矢印キーによる roving tabindex が無い状態で `role="tab"` を使うのは誤用です。ステータス絞り込み（`VisitListSearch`）のような排他トグル群は `role="group"` + `aria-pressed` で公開します。
- **`listbox` を名乗るならキーボード操作を必ず実装すること**: 並び順ドロップダウン（`SortSelect`）は WAI-ARIA の Listbox パターンで実装しています。展開時はフォーカスを `ul[role="listbox"]`（`tabIndex={-1}`）へ移し、ハイライト位置は `aria-activedescendant` で公開します（個々の `li` はフォーカスを持ちません）。↑↓（端で循環）・Home・End で移動、Enter / Space で確定、Escape で確定せず閉じてトリガーへフォーカスを戻す、Tab で確定せず閉じる、までが最低要件です。`role="option"` を `onClick` だけで実装するとマウス専用の UI になります。ハイライトの見た目は `.quick-sort-option.is-active`（選択中の `.is-selected` と重なるため枠線で区別）が担当します。
- **`menu` を名乗るならキーボード操作を必ず実装すること**: サイドバーの「…」メニュー（`SidebarHeader`）は WAI-ARIA の Menu Button パターンです。トリガーに `aria-haspopup="menu"` / `aria-expanded` / `aria-controls`、メニューに `aria-labelledby` を付け、開いたら先頭の項目へフォーカスを移します（項目は `tabIndex={-1}`）。↑↓（端で循環）・Home・End で押せる項目だけを移動し、Escape で閉じてトリガーへ戻す、Tab で確定せず閉じる、までが最低要件です。項目を選んだときは実行前にフォーカスをトリガーへ戻してください（メニューが消えるとフォーカスが `body` へ落ち、開いたモーダルを閉じた後の戻り先も失われます）。
- フォームの `label` は `htmlFor` と `id` で入力欄と紐づけること。ボタン群には `role="group"` + `aria-labelledby`（`.form-group-label`）を使用します。placeholder はラベルの代わりになりません（検索欄は `.sr-only` のラベルを付ける）。
- 絞り込み結果の件数など、操作の結果として変わる情報は `role="status"` + `aria-live="polite"` のライブリージョンで伝えること（`VisitListHeader` の `.sr-only` 要素）。見た目の数字だけを更新しても支援技術には伝わりません。
- **飾りのアニメーションを無限に繰り返さないこと**: 選択中のカード（`selectedPulse`）は選んだ瞬間に 1 回だけ光らせ、地図の選択中のピン（`pulseRingSelected`）は位置を探せるよう 3 回で止めます。選択中であることは枠や色で伝わるため、ずっと脈打たせると内容を読む間も明滅し続けます。無限ループは、ホバー中のピンの波紋・現在地の波紋・読み込み中の表示（スピナー、スケルトン）のように、その状態の間だけ動いていること自体が情報になるものに限ります。一覧カードはホバーで浮かせず（`transform` を付けない）、面の色・枠・影だけで示してください（ポインタを縦に動かすとカードが次々と上下にぶれます）。
- アニメーションは `prefers-reduced-motion` を尊重すること。CSS は `base.css` の共通ブロックが担い、JS 由来のもの（Leaflet の `flyTo`、`scrollIntoView`）は `utils/motion.ts` の `prefersReducedMotion()` / `getScrollBehavior()` を経由させます。
- テーマは初期描画前に `layout.tsx` のインラインスクリプトが `html` へ `light-theme` を付与します（ちらつき防止）。判定ロジックを変更する際は `utils/theme.ts` の `getInitialTheme()` と必ず揃えてください。保存値が無い場合は OS の `prefers-color-scheme` に従います。

## 3. ビルドモード
- local／apiの判定は`frontend/dataSource.ts`の`DATA_SOURCE`を使います。`process.env.NEXT_PUBLIC_DATA_SOURCE === "api"`のような個別判定を増やさないでください。不正値はbasePath・Repository・Service Workerが食い違うため、暗黙のフォールバックではなくビルドエラーにします。
